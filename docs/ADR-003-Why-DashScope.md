# ADR-003: 为什么选择通义千问（DashScope）而非 OpenAI API

## 状态
已接受

## 背景
项目需要接入大模型 API 用于：
1. 漏洞研判报告生成（CoT Prompt + Few-shot）
2. 多模型集成研判（qwen-turbo/plus/max 并发调用）
3. RAG 知识库 Embedding（text-embedding-v3）

## 考虑的方案

### 方案 A: 通义千问（阿里云 DashScope API）
- **优点**：国内合规、中文理解能力强、Embedding 和 LLM 一站式服务、价格相对低廉、有免费额度
- **缺点**：模型能力不如 GPT-4、对英文场景优化有限

### 方案 B: OpenAI API（GPT-4 / GPT-3.5-turbo）
- **优点**：模型能力强、社区活跃、生态丰富
- **缺点**：国内需 VPN 才能访问、合规风险、中文任务价格更高、不提供国内合规保障

### 方案 C: 本地开源 LLM（Llama3 / Qwen2.5）
- **优点**：完全离线、零 API 成本、数据不离开本地
- **缺点**：需要高性能 GPU（至少 16GB 显存）、推理速度慢、准确率不如商业模型

### 方案 D: 其他国内模型（智谱 GLM / 百度文心）
- **优点**：国内合规
- **缺点**：需要分别申请 API Key（多套认证）、Embedding 和 LLM 需要不同服务

## 决策
**选择方案 A: 通义千问（DashScope API）**

## 理由
1. **国内合规**：使用国内云服务，合规风险低，适合教学与研究场景
2. **中文优化**：通义千问对中文漏洞术语（如"SQL注入"、"命令执行"）的理解优于 GPT 系列
3. **一站式服务**：DashScope 同时提供 LLM（text-gen）和 Embedding（text-embedding-v3）两个 API，减少接入工作量
4. **成本可控**：有免费调用额度，本项目在免费额度内即可运行
5. **国内访问**：无需 VPN，部署和调试方便

## 后果

**正面**：
- 一套 API Key 即可调用 LLM + Embedding，减少配置复杂度
- 中文漏洞术语理解好，研判报告质量更高
- 国内网络直连，响应延迟低于 OpenAI

**负面**：
- 相比 GPT-4，模型推理能力有差距（但对漏洞研判任务足够）
- 模型版本跟随云服务更新，存在 API 兼容风险（但 DashScope 版本控制较好）
- 依赖阿里云服务，网络中断时无法使用（可降级为本地模拟模式）

## 未来可考虑
- 作为对比实验，接入 Ollama + Qwen2.5-7B 本地模型进行离线对比
- 在 AgentBench 框架中引入 OpenAI GPT-4 作为 SOTA 对照组
