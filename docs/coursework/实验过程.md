## 实验三：流式扫描验证

**接口**：`POST /api/scan/stream`

请求体示例：
```json
{"target_url": "http://127.0.0.1:18789", "model": "qwen-turbo"}
```

响应流示例（SSE）：
```
data: {"type": "dag_order", "order": ["CS0048","CWE-89","CWE-78","AML.T0051"]}
data: {"type": "start", "index": 1, "name": "API未授权访问配置泄露", "cve": "CS0048"}
data: {"type": "log", "message": "正在执行漏洞探测..."}
data: {"type": "result", "name": "API未授权访问配置泄露", "cve": "CS0048", "status": "success"}
data: {"type": "attack_graph", "analysis": {"overall_risk_score": 10.0, ...}}
data: {"type": "complete"}
```

SSE 协议当前支持 5 种事件类型：
- `dag_order` — DAG 调度顺序
- `start` — 开始扫描某个漏洞
- `log` — 实时日志推送
- `result` — 某个漏洞的扫描结果
- `attack_graph` — 攻击图关联分析
- `complete` — 全部扫描完成

## 实验六：多模型集成研判

**接口**：`POST /api/judge/ensemble`

```json
{
  "models": ["qwen-turbo", "qwen-plus", "qwen-max"]
}
```

返回各模型的独立报告 + 一致性分析（consensus_level）。

## 实验七：自动补丁闭环

**接口**：`POST /api/auto-patch/full-cycle`

```json
{"cve_id": "CS0048", "target_url": "http://127.0.0.1:18789"}
```

四步流程：生成补丁 → Docker 写入 → 重启容器 → 重新扫描验证

## 实验八：红蓝对抗推演

**接口**：`POST /api/adversarial/run`

```json

```

返回多回合计分结果 + 每步攻击记录 + 最终总结。
